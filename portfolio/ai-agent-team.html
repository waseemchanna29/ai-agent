01Executive Summary

The system turns a one-line business request into a specified, implemented, tested and documented software change. Four AI agents, each with a single responsibility, work like a small delivery team. A lightweight orchestrator assigns the work, enforces boundaries between the agents and stops for human approval at every decision point.

02System Architecture

Isolation

Least-privilege agents

Every agent can read the whole project but write only its own area. QA can report a bug, never patch it.

Governance

Two-level rules

Global rules apply to every project; per-project rules override them. Both are injected into every run.

Traceability

File-based handoffs

Specs, handoffs, decisions and a status board give a complete, human-readable audit trail.

03How the Agents Work Together

Work moves through four phases. After each phase the orchestrator pauses at an approval gate: the owner approves, sends feedback (the same agent continues its session), or stops and resumes later.

Maintenance mode: test first, fix only after approval

At every approval gate the owner chooses

Approve

Move to the next phase

The phase is marked done, documents are exported to PDF and the next agent starts with the handoff.

Feedback

Same agent continues

Answers or corrections go back into the agent's own session, so nothing is lost or re-explained.

Stop

Pause and resume later

State is saved per project; the pipeline restarts from any phase with a single command.

04Agent ⇄ Trello Communication

The team has its own Trello member account. Mentioning it in a card comment or description is the only trigger: the bridge reads the whole card (description, checklists, attachments, comment history), decides which agent should act, runs it and replies on the card, mentioning the person who asked.

Intent routing

  • Keywords first (English and Roman Urdu): requirements, dev/fix, qa/test, docs, in the order written. Several agents can be chained in one comment.
  • Small model fallback: if no agent is named, a lightweight model classifies the request.
  • Follow-ups without an agent name resume the session of the last agent on that card.
  • Undo restores the backup from the last development run.

Security & reliability

  • HMAC-SHA1 signature check on every webhook; invalid requests get 401.
  • Each Trello action is processed once, even if Trello retries the delivery.
  • The agent ignores its own comments and edits, which prevents feedback loops.
  • Credentials stay in a local environment file and are sent only in request headers.

05Card Lifecycle on the Board

06Professional Documentation Output

Every client document gets a cover page, running headers, page numbers and a closing Document Version History table (Version 1, 2, 3 …). Requirement changes never overwrite history: the previous SRS is frozen, a change-log entry records what was added, changed or removed, and affected agents are notified.
