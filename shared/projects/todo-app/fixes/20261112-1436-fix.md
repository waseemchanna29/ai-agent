## Proposed changes
Additive only. I will add 6 routes, 3 Blade views, 1 nav link, and 1 test file.
**No change to `UsersController.php`** (already present and verified).

**1. `routes/web.php` — add 6 routes inside the existing `auth` group** (after the task
routes), plus `use App\Http\Controllers\UsersController;` at the top.
```php
// before: (only task routes inside Route::middleware('auth')->group)
Route::delete('/tasks/{task}', [TaskController::class, 'destroy'])->name('tasks.destroy');

// after: task routes unchanged, then —
Route::get('/users',             [UsersController::class, 'index'])->name('users.index');
Route::get('/users/create',      [UsersController::class, 'create'])->name('users.create');
Route::post('/users',            [UsersController::class, 'store'])->name('users.store');
Route::get('/users/{user}/edit', [UsersController::class, 'edit'])->name('users.edit');
Route::put('/users/{user}',      [UsersController::class, 'update'])->name('users.update');
Route::delete('/users/{user}',   [UsersController::class, 'destroy'])->name('users.destroy');
```
(Route names match exactly what the controller already redirects to / the views will POST to.)

**2. New `resources/views/users/index.blade.php`** — mirrors the task list card style
(reuses existing CSS: `.card`, `.btn-primary`, `.btn-danger`, `.empty`, `.muted`).
```blade
@extends('layouts.app')
@section('content')
  <div class="card">
    <h1>Users</h1>
    <p><a href="{{ route('users.create') }}" class="btn-primary" style="...">Add user</a></p>
    @forelse ($users as $u)   {{-- name, email, created_at, Edit link, Delete form --}}
      ...
      <form method="POST" action="{{ route('users.destroy', $u) }}"
            onsubmit="return confirm('Delete this user?');">
        @csrf @method('DELETE')
        <button class="btn-danger">Delete</button>
      </form>
    @empty
      <p class="empty">No users yet.</p>
    @endforelse
    @if ($users->hasPages()) {{ $users->links() }} @endif   {{-- see pagination note in Risk --}}
  </div>
@endsection
```

**3. New `resources/views/users/create.blade.php`** — name / email / password /
password_confirmation form → `route('users.store')` (`@csrf`), "Cancel" link back to
`users.index`. Mirrors `resources/views/auth/register.blade.php`.

**4. New `resources/views/users/edit.blade.php`** — same fields pre-filled from `$user`

## Risk
- **Authorization gap (unchanged from 11:12 — still needs an owner decision).** There is
  **no admin role** (requirements v2 §2: *"No admin role in this version."*). Behind only the
  `auth` middleware, **every logged-in user can add/edit/delete any other user and reset their
  passwords.** For a school demo this may be fine.
  - **Assumption if no answer:** ship it behind `auth` (matches current scope, smallest change).
  - **Recommended alternative:** add an `is_admin` boolean (one migration) and gate the module
    to admins. I will NOT do this unless you say so — it changes the data model and the spec.
- **Pagination markup is unstyled.** The controller uses `->paginate(15)`; Laravel 12's
  default `->links()` emits **Tailwind** classes, but this app compiles no Tailwind (plain
  inline CSS). Links still work via `?page=`, just visually plain. I guard with
  `@if ($users->hasPages())` so nothing shows until there are 16+ users. Acceptable for a
  school app; say the word if you'd rather I drop pagination or hand-style it.
- **Cascade delete.** Deleting a user also deletes all their tasks (existing FK
  `cascadeOnDelete`). Permanent, no undo.
- **Self-delete guard.** Already in the controller (`abort_if($user->id === auth id, 403)`),
  so you can't delete the account you're logged in with.
- **Requirements out of sync.** REQUIREMENTS.md v2 has no user-management FRs. After this is
  applied I'll flag the requirements agent (in my handoff) to add FRs and bump the version so
  QA/docs catch up. I won't edit their files.
- **Low technical risk otherwise.** Purely additive: `web.php` (2 insertions), one nav line,
  3 new view files, 1 new test file. No existing controller/model/migration is modified.
