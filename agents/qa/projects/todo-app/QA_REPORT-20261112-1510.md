## 1. What I was asked to test
Owner request: test the new "task due date" feature (FR-8) — adding a due date, editing it,
empty date, past date, and sorting the list by due date — and confirm the older features
still work.

## 2. Findings

### 2.1 FR-8 is not in the requirements
REQUIREMENTS.md is at **v2** and defines **FR-1 through FR-7 only**. There is no FR-8.
On the contrary, the spec explicitly excludes due dates:
- §10 Assumption 5: *"No due dates, priority, categories, or search in this version."*
- §10 Open question: *"Should tasks have a due date ... later, or keep it minimal?"*

The requirements `CHANGELOG.md` has no entry adding a due date. So "FR-8" does not yet
exist as an approved requirement.

### 2.2 FR-8 is not implemented in the code
Code reviewed under `C:\xampp\htdocs\todo-app`. No due-date support anywhere:

| Layer | Expected for FR-8 | Actual |
|-------|-------------------|--------|
| Migration `...create_tasks_table.php` | a `due_date` (date/datetime, nullable) column | only `id, user_id, title, is_completed, timestamps` — **no due_date** |
| `app/Models/Task.php` | `due_date` in `$fillable`, date cast | `$fillable = ['title','is_completed']`; casts only `is_completed` — **no due_date** |
| `TaskController::store` | validate + save a due date | validates `title` only; creates `title` + `is_completed` — **no due_date** |
| Edit capability | a route + form to edit a task (title/due date) | **none** — `update()` only toggles `is_completed`; there is no `tasks.edit`/show route or edit form at all |
| `resources/views/tasks/index.blade.php` | due-date input + display | add-form has only a `title` text field; list shows title + toggle + delete — **no due date** |
| List ordering | sort by due date | `index()` uses `->latest()` (created_at desc) only — **no due-date sort** |

Grep for `due` across app code (excluding `vendor/`) returns only `DEV_NOTES.md` and
`README.md`, both stating *"no due dates"* as out-of-scope. DEV_NOTES "Known limitations"
still reads: *"no due dates/priority/categories/search."*

Because none of the five requested behaviours (add, edit, empty, past, sort) have any
code behind them, there is nothing to exercise. The five FR-8 scenarios are therefore
**NOT TESTED (blocked — feature absent)**, not FAIL.

## 6. Recommendations

1. **Spec first.** Requirements agent should add **FR-8** to REQUIREMENTS.md with clear
   acceptance criteria, especially the two ambiguous points:
   - Past due date → reject, or accept and flag "overdue"?
   - Sort order → by due date ascending? Where do tasks with **no** due date go (top/bottom)?
   And whether due-date sort **replaces** or **coexists with** FR-2's "newest-first" rule.
2. **Then implement.** Development needs: a nullable `due_date` column (migration), add it
   to the `Task` model (`$fillable` + date cast), validation in `store` (nullable date), a
   **task-edit route + form** (none exists today — editing a due date is impossible without
   it), the input/display in the Blade view, and the chosen ordering in `index()`.
3. **I have pre-written the FR-8 test matrix** (FR-8.1–8.8) in `TEST_PLAN.md`; I will turn
   those into automated tests and run add/edit/empty/past/sort once the feature lands.
4. Update DEV_NOTES.md "Known limitations" (still says "no due dates") when FR-8 ships.
