## 4. Bugs

### BUG-1 — High — Creating a user via the Users module crashes (500); no user is saved
- **File:** `app/Http/Controllers/UsersController.php:47-48`
- **Code:**
  ```php
  User::create([
      'name'  => $validated['name1'],   // key is 'name',  not 'name1'
      'email' => $validated['email1'],  // key is 'email', not 'email1'
      ...
  ```
- **Steps to reproduce:** Log in → Users → Add User → fill name/email/password/status (any status)
  → Submit. Also reproduced by `php artisan test` (the two failing tests above).
- **Expected:** User is created with the submitted name/email and redirected to `/users` with
  "User created."
- **Actual:** `ErrorException: Undefined array key "name1"` → HTTP 500. No user is inserted.
  (Validation still runs first, so invalid-status/duplicate-email rejection works — but **no valid
  create ever succeeds**.)
- **Regression:** The pre-card backup
  (`backups/trello-2fbd9b-20261113-091816/app/Http/Controllers/UsersController.php:45-46`) used the
  correct keys `$validated['name']` / `$validated['email']`. This card's edit (adding the `status`
  line to the `create()` array) mangled those two keys. `update()` at lines 77-79 is **correct** —
  only `store()` is broken.
- **Fix:** change `$validated['name1']` → `$validated['name']` and `$validated['email1']` →
  `$validated['email']`.

No other bugs found. The login/status logic, the "status not leaked" ordering, update/deactivate,
and all task/auth flows are correct.
